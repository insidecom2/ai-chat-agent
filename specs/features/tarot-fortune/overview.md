# Tarot Fortune

## Goal

เพิ่มตัวเลือกดูดวงไพ่ทาโรต์ในหน้า `/fortune` ให้ผู้ใช้เห็นสำรับไพ่ 78 ใบที่สับลำดับใหม่เมื่อเริ่มการทำนาย เลือกไพ่ชื่อภาษาไทยให้ครบ 10 ใบ แล้วส่งชื่อไพ่ที่เลือกไปยัง `POST /api/fortune` เพื่อให้ AI gateway วิเคราะห์

## Scope

- เพิ่มข้อมูลไพ่ทาโรต์มาตรฐาน 78 ใบใน `lib/tarot-deck.json` โดยมีชื่ออังกฤษอ้างอิง, `name_th` สำหรับ UI/API และคำอธิบายภาษาไทย
- ใช้ `name_th` เป็นชื่อไพ่หลักในการเลือกและส่งให้ AI
- สับลำดับสำรับใหม่เมื่อเริ่มการทำนาย/กดเริ่มรายการใหม่
- เพิ่ม UI แสดงไพ่ทั้ง 78 ใบและสถานะการเลือก
- บังคับเลือกไพ่ให้ครบ 10 ใบก่อน submit และไม่ให้เลือกเกิน 10 ใบ
- เพิ่ม `tarotCards` ใน request ของ fortune API และตรวจสอบว่าเป็นชื่อไพ่ที่ถูกต้อง 10 ชื่อไม่ซ้ำ
- เพิ่มคำสั่งในข้อความไป AI ว่าให้วิเคราะห์ไพ่ทาโรต์จากไพ่ที่เลือก
- แสดงไพ่ที่เลือกในผลการทำนาย

## Out of Scope

- การบันทึกผลไพ่ทาโรต์ลงฐานข้อมูล
- ไพ่กลับหัว (reversed cards)
- การเพิ่ม/แก้ไขสำรับไพ่จากผู้ใช้
- การเปลี่ยน AI gateway หรือ model ที่ใช้อยู่

## Acceptance Criteria

1. เมื่อเปิดหน้าแบบฟอร์มดูดวงหรือเริ่มรายการใหม่ ระบบแสดงไพ่ทาโรต์ 78 ใบ และชื่อภาษาไทยของแต่ละใบไม่ซ้ำกัน
2. เมื่อเริ่มรายการทำนายใหม่ ลำดับที่แสดงของสำรับถูกสุ่มใหม่
3. ผู้ใช้เลือกไพ่ได้ไม่เกิน 10 ใบ และ UI แสดงจำนวนที่เลือกปัจจุบัน
4. ระบบไม่ submit เมื่อเลือกไม่ครบ 10 ใบ และแสดงข้อความแจ้งให้เลือกไพ่เพิ่ม
5. เมื่อเลือกครบ 10 ใบ ระบบ submit ชื่อไพ่ภาษาไทยทั้ง 10 ใบไปยัง `POST /api/fortune`
6. API ปฏิเสธ request ที่มีไพ่ไม่ครบ 10 ใบ, ชื่อซ้ำ, หรือชื่อที่ไม่อยู่ในสำรับ 78 ใบ
7. ข้อความที่ส่งต่อไปยัง AI ระบุให้วิเคราะห์ไพ่ทาโรต์จากชื่อไพ่ที่ผู้ใช้เลือก
8. หน้าผลลัพธ์แสดงชื่อไพ่ทั้ง 10 ใบและรองรับ loading/error state เดิมของ fortune flow
9. การเลือกไพ่ไม่ทำให้ข้อมูลชื่อ วันเกิด หัวข้อ หรือข้อความเพิ่มเติมของฟอร์มเดิมสูญหาย

## API Candidate

Request เดิมของ `POST /api/fortune` เพิ่ม field:

```ts
tarotCards: string[]
```

โดยมีค่าเป็นชื่อไพ่ภาษาไทย 10 ชื่อที่ไม่ซ้ำกัน ส่วน field เดิมยังคงใช้งานได้ตามเดิม โดย `tarotCards` ที่ไม่มีค่าให้ถือว่าเป็นการดูดวงแบบเดิมเพื่อ compatibility

## Event Flow

1. หน้า fortune สร้างสำรับ 78 ใบและสับลำดับเมื่อเริ่มรายการ
2. ผู้ใช้กดเลือกไพ่จากสำรับ ระบบเพิ่ม/นำไพ่ออกจาก selection โดยไม่ให้เกิน 10 ใบ
3. ผู้ใช้ submit เมื่อเลือกครบ 10 ใบ
4. Client ส่งข้อมูลฟอร์มเดิมพร้อม `tarotCards` ไปยัง `/api/fortune`
5. API ตรวจสอบข้อมูลและสร้าง user prompt ที่มีรายชื่อไพ่ภาษาไทย
6. API proxy stream คำตอบจาก AI gateway กลับให้ client
7. Client แสดงรายชื่อไพ่ที่เลือกและผลวิเคราะห์แบบ stream

## Edge Cases

- กด submit ขณะเลือกไพ่ 0–9 ใบ
- พยายามเลือกใบที่ 11
- request ถูกแก้ไขจาก client ให้มีชื่อซ้ำ/ชื่อปลอม/จำนวนไม่ครบ
- AI gateway timeout หรือส่ง response ว่าง
- กดเริ่มรายการใหม่หลังการทำนายสำเร็จ
- สลับ dark mode หรือหน้าจอแคบขณะเลือกไพ่

## Affected Layers

- Frontend: `app/fortune/page.tsx`, `components/FortuneForm.tsx`, `components/FortuneResult.tsx`, tarot data/helper
- Backend: `app/api/fortune/route.ts`, fortune request normalization/prompt helper
- Tests: fortune request, prompt, route, form และ result behavior
- Database: ไม่ได้รับผลกระทบ

## Constraints and Decisions

- ใช้ชื่อไพ่ภาษาไทยตามที่ผู้ใช้ยืนยัน
- เลือกครบ 10 ใบ ไม่ใช่เลือกได้สูงสุด 10 ใบ
- การสุ่มมีไว้เพื่อสับลำดับสำรับตอนเริ่มรายการ ไพ่ที่ส่งให้ AI คือไพ่ 10 ใบที่ผู้ใช้เลือก ไม่มีการสุ่มเพิ่มหลัง submit
- คง endpoint และ AI gateway เดิมไว้
